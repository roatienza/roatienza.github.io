Tag fix — why this render differs from yesterday's

Yesterday's A/B (onit_dpo_ab_v1) was rendered with the en-v1 text frontend, whose tag regex only matched single-word tags like <breath>. The trained colon tags (<emo:tender>, <ev:laughing>, </span:whisper>) slipped through, got their : rewritten to , and their brackets padded away, and were pronounced as text — "emo,tender close the book…". Every one of the 75 prompts carries tags, so both arms were polluted (UTMOS base 3.17 vs DPO 2.66, WER 0.30 vs 0.36, and a significant base win, z = 5.21) — much of it the tags being read aloud, not the adapter.

Fix (2026-11-21, one line in text_frontend_en.py): the tag regex now round-trips </?(emo|ev|span):…> verbatim, so the byte tokenizer emits the trained tag ids the model saw in training (1.17M tagged manifest rows).
