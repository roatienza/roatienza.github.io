Homograph pronunciation: what the fix helps, and what it breaks

Paired listening demo · 31 sentences · same checkpoint, same steps, same seed · the only difference between the two clips is the spelling of one word

English homographs are spelled the same and said differently: a lead pipe vs lead the team, a bass vs play bass. A text-to-speech model sees only letters, so it has to guess. The fix is to rewrite the word as a spelling that can only be said one way — lead→led, bow→bough — chosen by looking for context words nearby.

The rewrite is a guess twice over: first that the context words were found, second that the replacement spelling actually makes the model say the intended sounds. Both are measurable, and on this page the second one fails often enough that the feature is not shipped.

The rule breaks 1 sentences the model already got right

This is the finding a one-armed demo cannot show, because a success and a failure look identical from one side: both are just audio. Playing the plain clip first shows the model was already correct, and the fixed clip then shows it being made wrong.

The worst case is dove: plain text "she dove into the pool" already produced the intended doʊv. The rule rewrote it to dohv and the model said dɑv — a pronunciation that is not a word. The replacement spelling never appears in English, so the model has no reason to map it to the sounds the table assumed.

Why the headline number is a range, not a point

The published figure was 22/27 = 0.815. It cannot be reproduced, and the reason is in the runtime: SamplingRequest.seed defaults to None, and inference_runtime.py:1207 turns None into secrets.randbits(63). The first end-to-end render passed no seed, so that number is one draw from a distribution nobody recorded. Re-rendering identical text, steps and checkpoint gives 21/27, with three items swapping verdict.

So the same 5 seeds were run on both arms, paired per seed (item i of seed s uses seed s*1000+i in each arm, so the arms differ only in spelling):

How this was measured

Both arms are the production English checkpoint Cs2rft1d_67m_ema600.pt at 40 steps, rendered through training/serve_worker.py --mode jobs. The plain arm runs in a git worktree of the branch's parent commit, where prepare_spoken_text exists but does not rewrite homographs; the fix arm runs on the branch. Neither is a flag that pretends to be the other — the pre-fix behaviour is a real checkout of the pre-fix code.

A control confirms the pairing: the 13 sentences the rule does not touch are bit-identical between arms, and all 18 it does touch differ. So every audible difference on this page is the rewrite and nothing else.

Scoring is the recogniser's own decode, compared character by character against both readings (facebook/wav2vec2-lv-60-espeak-cv-ft). The page reports the exact-match verdict only. A paired forced-choice instrument was also run and returned 27/27, which is an artefact: a forced choice cannot answer “neither”, so a third pronunciation is always nearer one of the two. Those rows are labelled wrong here even when forced choice called them right.

What is not shown, and would change the answer

This checkpoint was trained on text that was not rewritten. Every clip here asks it to say a spelling it may never have seen — which is exactly why dohv and dohz fail. A model trained on the rewritten text is the real test of the approach, and that run has not been done. Until it is, these numbers measure a frozen model meeting new spellings, not the ceiling of the idea.
