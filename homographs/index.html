One homograph fix, two models

The reading is decided once, by context. The spelling is measured per model. Same code, both engines, and nothing lost on either — which the single shared table could not do.

The rule that shipped on 2026-10-28 helped Cs2 by +5 and hurt the 4B by −2, because one carrier table was applied to whichever model was serving. dohv works on Cs2 (437-entry byte vocabulary) and fails on the 4B, whose tokenizer splits it ['do','hv'] and says “duhiv”. The carrier was chosen by looking at it, never by asking the model. Now each model is asked.

The defect the corpus check found

974 688 rows across four manifests. 26.9 % of Cs2's rewrites and 21.2 % of the 4B's were applied where no cue was in range — the frequency fallback chose the reading. read falls back to the present tense, so these become reed. Listen to what the method does when nobody asked it about the sentence.

corpus read reading A past tense; no cue in range, so the default (B, present) chose
plain too long, didn't read
common too long, didn't read
corpus read reading A a noun; the B cue list does not cover it and nothing else does
plain we all met for a cold read in a conference room
common we all met for a cold read in a conference room
corpus read reading A `never` is in the B cue list, so this one arrives LABELLED as cue-decided
plain i never read that
common i never read that

These three are rendered on Cs2 from the corpus text itself, both arms, same seed. Step.provenance now records cue vs default, so this is counted rather than argued — but counting it did not fix it. The cue list still needs the past-tense cases.
